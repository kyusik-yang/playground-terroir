# Data files

All files are generated by the scripts in `../../scripts/` and are safe to regenerate. Do not hand-edit them.
Curated text (village profiles) lives in `../../content/villages.json`.

| File | Built by | What it holds |
|---|---|---|
| `index.json` | `03_export.py` (+ `white` flags from `06_villages.py`) | Search index of every mapped feature and region bounds |
| `terroir-overview.geojson` | `03_export.py` | Light outlines of village appellations and grand crus for zoomed-out views |
| `terroir-<region>.geojson` | `03_export.py` (+ `white` flags from `06_villages.py`) | Full-detail appellations, premier cru climats and grand crus for one region |
| `villages.json` | `06_villages.py` | The 15 profiled villages, curated text plus computed statistics |
| `transects.json` | `05_transects.py` | Slope cross-sections |
| `climate.json` | `04_climate.py` | Yearly climate indices 1950–2025 for four sites |
| `sources.json` | hand-maintained | Data sources, licences, access dates, quotes. Optional fields `group` (`data`, `check`, `software`), `download`, `download_bytes`, and `fact_check` (tallies of the colour-rule check, with `in_force` for the re-check against homologated texts). Update `fact_check` whenever `content/scope.json` changes |

Region ids: `chablis`, `cote-de-beaune`, `cote-chalonnaise`, `maconnais` (north to south).
Levels: `grand-cru`, `premier-cru`, `village` (and `regional`, `none` in transects).

## index.json

```
{ "generated": ISO, "source": {inao:{...}, dem:{...}},
  "regions": [{ "id", "name", "file", "bounds": [[south, west], [north, east]], "counts": {appellation, climat, grand_cru}, "bytes" }],
  "features": [{ "id", "kind": "appellation"|"climat"|"grand_cru", "level", "name", "full", "app", "region",
                 "village": profiled village id or null, "center": [lat, lng], "bbox": [south, west, north, east],
                 "area_ha", "elev_mean", "aspect_label", "white": true|false|null }] }
```
`name` is the short display name ("Perrières", "Montrachet", "Meursault"). `full` is the INAO denomination
("Meursault premier cru Perrières"). `app` is the INAO appellation it belongs to.

## terroir-<region>.geojson and terroir-overview.geojson

FeatureCollection. Paint order is already correct (large under small, Corton under Corton-Charlemagne).
Region file feature properties:

```
id, kind, level, name, full, app, region, communes: [names], area_ha,
elev: [min, mean, max] (m), slope (mean degrees), slope_pct (mean %), aspect (mean bearing the slope faces, 0 = north, null when flat),
aspect_label ("ESE", "flat"...), aspect_hist: 8 shares for N, NE, E, SE, S, SW, W, NW of ground sloping at least 2 degrees,
village: profiled village id or null, white: true | false | null (appellation allows white wine, null = not verified)
appellation only: pc_area_ha (all premier cru land in the appellation, or null when the appellation has no premier cru land),
  n_climats (named premier cru climats in INAO data)
Petit Chablis: display_note "petit-chablis-exclusive" (shape shows land entitled to Petit Chablis but not Chablis.
  area_ha, elev and the other statistics, here and in index.json, describe the whole delimitation, which contains all of Chablis)
Corton-Charlemagne: contains: ["Charlemagne"] (the Charlemagne grand cru lies inside it and is not drawn)
```
Overview features carry only `id, kind, level, name, region, village`.

Caveat to show in the UI: INAO's digital delimitation does not yet name every climat. In Chablis only ten
premier cru climats are digitised by name, all outside the commune of Chablis itself. Several climat names nest
(Morgeot contains Les Brussonnes, La Boudriotte, etc.) and some ground carries two names (Meursault premier cru
Blagny and Blagny premier cru are the same land, for white and red wine respectively).

## villages.json

```
{ "generated", "notes": [..],
  "villages": [{
     "id", "name", "region", "regionName", "apps": [INAO appellations], "communes": [..],
     "levels": ["grand-cru", "premier-cru", "village"], "topLevel",
     "grape", "style", "tags": [..], "foodPairing", "priceRange", "producers": [..], "note",
     "flavor": {mineral, citrus, oak, body, floral} (0-100, editorial and subjective),
     "quiz": {style: [3], budget: [3], food: [4], level: [3]} (finder weights per answer option),
     "marker": [lat, lng], "markerSource",
     "climatsOfficial": {count, label, url, accessed}   (Chablis only: the official climat count, because INAO digitises only 10 of 40),
     "stats": {
        "area_ha": {grand_cru, premier_cru, village, total},   exclusive levels, hectares
        "n_climats", "grand_crus": [{name, area_ha, id}],   (id is missing for Corton-Charlemagne, see below)
        "all": {elev: [min, mean, max], slope, aspect, aspect_label, aspect_hist[8]},
        "by_level": {grand_cru: {...same} | null, premier_cru: {...} | null, village: {...} | null} },
     "featureIds": {appellation: [ids], grand_crus: [ids], climats: [largest 8 ids]} }] }
```
The Corton-Charlemagne profile covers a grand cru appellation only, so its premier cru and village areas are zero.
It measures the Corton-Charlemagne grand cru shape, so `featureIds.appellation` holds that grand cru id
(`grand-cru-corton-charlemagne`), `featureIds.grand_crus` and `featureIds.climats` are empty, and its one
`stats.grand_crus` entry has no `id`. The Petit Chablis profile measures only the land outside Chablis, as the map draws it.

## transects.json

```
{ "meta": {dem, classification, method},
  "transects": [{ "id", "title", "region", "anchors": [2 names], "start": [lat, lng], "end": [lat, lng],
     "anchor_points": [[lat, lng], [lat, lng]], "bearing_downslope", "length_m", "step_m": 10,
     "z": [elevation every step_m from start],
     "segments": [{from, to (metres from start), level, name, feature (id or ""), z: [min, max]}],
     "z_range": [min, max] }] }
```
Transects start upslope and run downslope. `level` is the highest classification containing the sample.
A segment's `feature` is usually an id from index.json. Regional segments carry ids of the regional Bourgogne
layer (`regional-bourgogne`, `regional-bourgogne-blanc-exclusif`), which are not in index.json and cannot be opened on the map.

## climate.json

```
{ "meta": {source, dataset, resolution, resolution_quote, models, era5_land_precip_nonnull_values, url, api, licence, licence_url,
            licence_quote, attribution_html, citation, accessed, timezone, years: [1950, 2025], baseline, recent,
            huglin_k, huglin_k_source, sites_source, caveats: [..]},
  "indices": {<key>: {label, period, unit}},   keys: gs_tmean, gdd10, huglin, spring_frost_days, spring_min_tmin, hot_days, gs_precip, sep_precip
  "sites": [{id, name, region, insee, lat, lng, grid_lat, grid_lng, grid_elevation, precip_grid_lat, precip_grid_lng,
             huglin_k, years: [..], <key>: [one value per year]}],
  "summary": {<site>: {<key>: {baseline_1961_1990, recent_2016_2025, delta, trend_per_decade, top3: [[year, v]], bottom3: [[year, v]]}}},
  "analogs": {<site>: [{site, window: [y0, y1], gs_tmean, target, diff, abs_diff, in_range}]} }
```
`precip_grid_*` is the ERA5 cell used for precipitation (temperature uses the ERA5-Land cell in `grid_*`).
Each analog is the other site's 10-year window whose mean `gs_tmean` is closest to `target`, this site's
2016–2025 mean. `diff` is the window mean minus the target. `in_range` is false when the target lies outside
every window mean of that site, so the window is only the nearest edge and not a real analog. One analog per other
site, sorted by `abs_diff`.
Site ids: `chablis`, `meursault`, `rully`, `fuisse`.
